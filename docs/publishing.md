# GitHub 公开发布流程

## 不直接公开当前私有仓库的历史

Creo `.prt.*` 等源文件已经出现在旧提交中；后续删除、`.gitignore` 或 `git rm --cached` 都不会移除旧历史。内部日志、厂商手册和旧资料也不应随历史推到新的公开仓库。

本项目采用**白名单、无 Git 历史的工作区快照**准备公开版本，不重写或删除私有开发仓库。STEP / 3MF 可保留，Creo 原生文件不进入快照。内部文档继续本地保留，不作为公开文档入口。

## 本地检查与导出

在私有研发仓库根目录运行：

```sh
python scripts/export-public.py --check
python scripts/test-public-export.py
python scripts/export-public.py --output out/github-preview
```

- `--check` 预览将收录和排除的文件。
- 只允许新建 `out/` 内的输出目录；已有目录会拒绝覆盖，不执行递归删除。
- 不带 `.git`、不创建仓库、不上传、不改写历史、不删除原文件。
- 白名单包含精简公开文档、代码 / 测试、DSP 必需产物、指定 PCB 文件、STEP / 3MF 以及必要第三方来源和许可文件。
- 测试和构建会在验证目录生成缓存、下载组件和临时产物；验证通过后再导出一个新的干净候选目录，不要直接打包测试现场。
- 生成的 `PUBLICATION_STATUS.json` 记录快照文件 SHA-256 与已知发布阻塞项。它不是敏感信息扫描或法律合规证明。

**当前输出只是本地审阅候选，不可直接当成已批准的开源发行版。** 自有材料已采用分层许可；LDAC / reference 适配代码权利仍待确认，状态保持 `blocked`。“引用 / 自行评估”说明不替代授权，导出工具不会自动提交或推送。详细边界见[许可说明](licenses.md)。

## 人工发布门禁

- [x] 自有材料采用分层许可并附范围、完整文本及第三方说明；仍需核对实际公开快照的一致性。
- [ ] codec 及其他第三方材料的分发权利与义务闭环，或已从公开版本中真正移除并回归验证。
- [ ] 查看完整导出清单，确认没有私有资料、凭据、个人数据或不可再分发的第三方素材。
- [ ] 检查 PCB 工程内部的作者、链接、嵌入图片和库 / 3D 模型授权。
- [ ] 在快照目录实际构建、运行主机回归并核对来源哈希；不依赖私有 docs 或外部本地文件。
- [ ] 检查 README、链接、硬件 / 机械文件、功能声明与当前版本一致。
- [ ] 选择 GitHub 仓库名称与可见性，确认公开范围后，才在快照目录建立新的初始提交。

不要在当前私有仓库直接添加公开 remote 并推送整个 main，也不要把私有历史 merge 到公开仓库。后续发布仍通过审查后的新快照或明确的公开分支流程进行。未获得明确目标和范围授权前，工具不执行 GitHub 网络操作。
